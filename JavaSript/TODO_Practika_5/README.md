Варіант 3: Task Management (Система управління задачами)

# Концепція програми
В основі створення програми лежить класичний архітектурний підхід, де логіка обробки даних 
повністю відокремлена від їхнього візуального відображення на веб-сторінці. Проєкт розроблено з використанням 
об'єктно-орієнтованого програмування на базі сучасного синтаксису ES6+.

Уся логіка додатку розділена на два рівні:

Рівень сутності (клас Task) - описує структуру окремої задачі, її властивості та інкапсулює 
методи для зміни її внутрішнього стану 
(наприклад, переведення у статус виконаної чи додавання тегів).

Рівень управління (клас TaskManager) - виступає в ролі локальної бази даних в оперативній пам'яті. 
Він містить масив усіх об'єктів та відповідає за глобальні операції - фільтрацію, пошук, видалення та розрахунок аналітики.

# Функціональні вимоги до системи
Для повноцінної роботи TODO-додатка було реалізувано наступны функціональні блоки:

1. Управління задачами (CRUD операції)
Створення (Create) - можливість додавання нової задачі через інтерактивну форму із зазначенням назви, опису, пріоритету, тегів та кінцевої дати виконання.
Перегляд (Read) - динамічне відображення списку задач у вигляді інформаційних карток.
Редагування (Update) - можливість зміни будь-яких полів існуючої задачі (включаючи її пріоритет та дату дедлайну) через завантаження даних у форму.
Видалення (Delete) - повне видалення задачі з системи за її унікальним ідентифікатором.

2. Фільтрація та контекстний пошук
   Фільтрація за статусом - розділення загального списку на категорії: "Всі задачи", "В черзі" (активні), "Виконані" та "Протерміновані".
Фільтрація за пріоритетом - відсікання задач за рівнями важливості ("Низький", "Середній", "Високий").
Фільтрація за тегами - інтерактивний відбір задач за допомогою кліку на кнопки-теги у спеціальній хмарі.
Контекстний пошук - миттєвий пошук потрібних карток за частковим збігом введених символів у полях назви або опису.

3. Аналітика та робота з датами
   Автоматичний розрахунок загальної кількості задач, кількості виконаних справ та протермінованих дедлайнів.
Обчислення відсотка успішності (прогресу) виконання плану.
Валідація дат - блокування можливості вибору минулих дат при створенні нових задач та автоматичне виявлення протермінованих задач наступного дня після завершення дедлайну.
Динамічне скидання фільтрів після збереження змін для запобігання візуального зникнення оновленої задачі з екрана.

# Нефункціональні вимоги: 
Нефункціональні вимоги мого проєкту
Нефункціональні вимоги описують якісні характеристики системи, її надійність, зручність використання та технічні обмеження, які забезпечують стабільну роботу додатку.

1. Автоматизоване тестування (Юніт-тести)
   Ця вимога забезпечує надійність, якість коду та легкість його супроводу за допомогою запусків ізольованого сценарію перевірки бізнес-логіки. У ході виконання тестів автоматично проходять такі перевірки:

Створення об'єкта класу Task, перевірка встановлення початкового статусу "pending", а також працездатність методів зміни цього статусу та керування масивом тегів.
Валідація роботи геттера протермінування, який має повертати позитивний результат для завдань із дедлайном у минулому.
Коректність виконання CRUD-операцій у менеджері, що підтверджується успішним динамічним оновленням властивостей об'єкта та його видаленням за індексом.
Працездатність алгоритмів фільтрації завдань за рівнем їхнього пріоритету та точність роботи контекстного пошуку за текстовим запитом.
Правильність формування структури об'єкта загальної статистики, повернення числового типу для відсотка виконання та хронологічного групування за датами.

2. Графічний веб-інтерфейс
   Ця вимога визначає рівень взаємодії користувача з додатком, його візуальне сприйняття та технічне середовище виконання:
Кросбраузерність - інтерфейс адаптований для однакового відображення та стабільної роботи у сучасних браузерах завдяки використанню чистого стандарту HTML5, CSS3-стилів та модульного JavaScript.
Зручність використання (Usability) - макет сторінки розділений на логічні зони (ліва колонка для роботи з формою, права - для пошуку та перегляду списку), що робить навігацію інтуїтивно зрозумілою.
Візуальна ергономіка - реалізовано швидке зчитування станів за допомогою колірного кодування, де виконані картки отримують зелене забарвлення, а протерміновані завдання чітко виділяються червоним кольором.
Продуктивність - обробка дій користувача та перемальовування елементів сторінки відбуваються миттєво на стороні клієнта в оперативній пам'яті браузера без затримок на запити до сервера.

## Опис структур даних проєкту

### 1. Клас Task (Об'єкт задачі)
Представляє окрему задачу в системі. Конструктор приймає об'єкт параметрів та розбирає його через деструктуризацію.
Властивості:
- id - унікальний числовий або текстовий ідентифікатор.
- title - назва задачі.
- description - опис задачі.
- status - поточний статус ("pending" або "completed").
- priority - рівень важливості ("low", "medium", "high").
- dueDate - дата виконання (об'єкт типу Date).
- tags - масив текстових тегів для фільтрації.

Методи:
- markComplete() - переводить задачу в статус "completed".
- markIncomplete() - повертає статус "pending".
- addTag(tag) - додає новий тег до масиву.
- removeTag(tag) - видаляє вказаний тег із масиву.
- геттер isOverdue - автоматично перевіряє, чи є дата виконання меншою за сьогоднішню (актуально для невиконаних задач, порівняння йде без врахування годин).

### 2. Клас TaskManager (Управління колекцією задач)
Містить масив задач та методи для обробки даних.
Методи:
- createTask(data) - створює екземпляр класу Task з використанням spread оператора для копіювання даних.
- updateTask(id, data) - знаходить задачу за id та оновлює її властивості. Використовує метод Object.entries для динамічного перебору ключів та значень.
- deleteTask(id) - видаляє задачу з масиву за її індексом.
- getTasksByStatus(status) - повертає масив задач із відповідним статусом.
- getTasksByPriority(priority) - фільтрує задачі за рівнем важливості.
- getOverdueTasks() - повертає список усіх протермінованих задач.
- getTasksByTag(tag) - шукає задачі, які містять певний тег.
- searchTasks(query) - здійснює контекстний пошук за назвою або описом без врахування регістру.
- getStats() - розраховує загальну кількість задач, кількість виконаних, активних та протермінованих.
- getCompletionRate() - повертає відсоток виконаних задач від загальної кількості.
- getTasksByDueDate() - групує задачі за датами виконання. Для сортування ключів-дат за хронологією застосовується метод Object.keys.
- getTotalActiveTasksCount() - демонструє використання методу Object.values для підрахунку активних та протермінованих задач із проміжного об'єкта.

## Структура файлів проєкту
- task.js - опис класу Task.
- taskManager.js - опис класу TaskManager та всієї логіки обробки даних.
- index.html - графічний веб-інтерфейс (TODO-додаток) з інтерактивною формою, кнопками дій та фільтрацією.
- index.js - консольний сценарій роботи програми для демонстрації CRUD операцій через Node.js.
- tests.js - набір автоматичних unit-тестів для перевірки всіх методів.
- package.json - конфігураційний файл для підтримки ES6 модулів (type: "module") в Node.js.

## Інструкція із запуску програми

### Спосіб 1. Запуск веб-інтерфейсу в браузері (через CLion)
Для візуальної демонстрації роботи TODO-додатка (створення, редагування, виконання та видалення задач):
- Відкрити файл index.html у редакторі CLion.
- Навести курсор миші на код програми - у правому верхньому кутку з'явиться панель із логотипами браузерів.
- Натиснути на іконку Chrome (або іншого браузера). CLion запустить локальний веб-сервер, і програма відкриється на сторінці з готовим інтерфейсом.

### Спосіб 2. Запуск у консолі через вбудований Terminal
Якщо потрібно запустити текстовий сценарій роботи або перевірити тести без відкриття браузера:
- У нижній частині вікна CLion знайти і відкрити вкладку Terminal. Вона автоматично відкриється у потрібній папці проєкту.
- Для демонстрації роботи логіки (CRUD операцій) ввести команду і натиснути Enter:
  node index.js
- Для перевірки всіх методів через автоматичні unit-тести ввести команду і натиснути Enter:
  node tests.js
